# agentic-mods

Claude Code mods for engineering work: safety guards, verification evidence, governance
checks, and delivery workflows. Each mod is an independent plugin built from one shared,
dependency-free core library.

**Status:** the mods build, type-check and pass `claude plugin validate` (Claude Code 2.1.332).
They have **not** been exercised in a running session yet, and there are **no tests yet**.
Both are planned for the next wave. CI and GitHub Actions are deferred.

## Install

Mods load from the session's mods folder. The first time the engine writes to that folder, it asks
whether to turn on the mods Claude writes in this session. Answer **Turn them on** to load them.

```bash
pnpm install
pnpm types:sync      # copy the engine's declarations (needs the plugin-authoring skill loaded)
pnpm build           # bundle every mod into mods/<name>/hooks/register.js
pnpm validate        # claude plugin validate for every mod, plus the native-list check
pnpm deploy:dev      # copy built mods into the session's dev-mods folder
```

Marketplace: `.claude-plugin/marketplace.json` lists all 40 mods (generated by `pnpm registry`).
Installing from a published marketplace path has not been tested.

## Mods (40)

**Safety and boundary:** command-guard (holds or refuses destructive commands, keeps secret files out
of edits and reads), mod-firewall (checks outbound requests and process launches by non-native mods),
incident-timeline (strict command profile while an incident is open).

**Visibility:** session-meter (context, cost, rate limits), cache-clock (estimated prompt-cache
lifetime), task-orientation (goal, task, blocker, next step), mission-control (subagent tree),
turn-replay (per-turn diffs), markdown-preview, switchboard (file collisions across sessions),
response-modes, next-steps.

**Verification and governance:** evidence-gate (runs configured checks, gates commit, push and PR),
change-contract, test-impact, review-tracker, pr-readiness, architecture-guard, migration-sentinel,
dependency-radar, performance-budget, debug-timeline, learning-ledger, worktree-orchestrator,
engineering-cockpit.

**Workflows:** workflow-conductor (runs feature, TDD, bug-fix, regression, refactoring, pull-request,
release, hotfix and incident workflows), tdd-conductor, regression-orchestrator, defect-protocol,
behavior-lock, contract-compatibility-guard, specification-guard, change-planner,
observability-verifier, release-conductor, ci-triage.

**Presentation:** boss-fight, code-pet, session-wrapped, commentary.

The full list, with the purpose of each mod, is in `registry/native-mods.json`.

## Commands (selection)

| Command | Mod | What it does |
|---|---|---|
| `/guard` | command-guard | settings, config problems, blocks this session |
| `/evidence run [check]` · `/evidence` | evidence-gate | run configured checks, show verdicts |
| `/contract set|allow|forbid|mode|show` | change-contract | scope for the change |
| `/impact` | test-impact | tests the working tree reaches |
| `/finding add|set|list` | review-tracker | review findings and lifecycle |
| `/pr-ready [description]` | pr-readiness | readiness verdict, drafted verification section |
| `/workflow start|status|advance|defer|cancel` | workflow-conductor | run a delivery workflow |
| `/tdd red|green|refactor|complete <test>` | tdd-conductor | TDD cycle with behavioral RED |
| `/regression assess|run` | regression-orchestrator | risk scope and its checks |
| `/incident open|event|mitigate|recover|close|postmortem` | incident-timeline | incident record |
| `/agentic status|doctor|privacy` | engineering-cockpit | overall state and config health |

## Configuration

Per repository, in `.agentic-mods/config.json`. Every field is optional; invalid fields are reported
and their defaults used.

```json
{
  "guard": { "confirmTier": "button" },
  "evidence": {
    "required": ["build", "test", "lint", "typecheck"],
    "commands": { "test": [["npm", "test"]], "typecheck": [["npx", "tsc", "--noEmit"]] },
    "maxAgeMinutes": 30,
    "gateMode": "enforce"
  },
  "contract": { "mode": "warn" },
  "architecture": { "mode": "warn", "layers": [] },
  "firewall": { "mode": "warn", "allowHosts": [], "allowProcesses": ["git"] }
}
```

Commands are argv arrays and run without a shell. Other state files live under `.agentic-mods/`
(see `docs/architecture.md`).

## Limits to know

- Evidence is only PASS after a configured command exits 0 under `/evidence run`. Observed tool
  output is never treated as a pass, because the engine's Bash result carries no exit code.
- Completion of a turn cannot be blocked. Gates attach to git commit, push and PR creation instead.
- Architecture and migration checks read the text of an edit. For an Edit that is only the new text,
  a violation that spans the edit boundary can be missed.
- Behavior lock reads exports as text. It does not resolve types.
- Third-party mods named in planning notes were not used. See `registry/external-mods.json`.
